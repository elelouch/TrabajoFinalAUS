# Calendarizacion
La calendarizacion de un Proyecto de software es una accion que distribuye el esfuerzo de estimado a
traves de la duracion planificada del Proyecto, asignando el esfuerzo a tareas especificas de ingenieria de software.

## Principios Basicos
- Compartimentalizacion: 
	- El Proyecto debe compartimentalizarse en actividades y tareas manejables. 
	- Para lograr la compartimentalizacion  se desglosan tanto el producto como el proceso. 

- Interdependencia: 
	- Debe determinarse la interdependencia de cada actividad o tarea compartimentalizadas. 
	- Algunas tareas deben sucederse en secuencia, otras en paralelo.
	- Algunas no pueden comenzar hasta que este disponible el producto operativo de otras. 
	Otras pueden realizarse de manera independiente.

- Validacion del esfuerzo:
	- Todo Proyecto tiene un numero definido de personas en el equipo.
	- Conforme ocurre la asignacion del tiempo, asegurarse que no se ha calendarizado mas que el numero de personal asignado.

- Asignacion de tiempo:
	- Cada tarea por calendarizar, debe asignarsele cierto numero de unidades de trabajo (ej: persona-dias de esfuerzo)
	- Cada tarea debe asignarsele una fecha de comienzo y conclusion, en funcion de las interdependencias

- Responsabilidades definidas:
	- Cada tarea por calendarizar debe tener un miembro especifico.

- Resultados definidos:
	- Cada tarea que se calendarice, debe tener un resultado definido.
	- Los productos operativos con frecuencia se combinan con productos operativos entregables.

- Hitos definidos:
	- Cada tarea o grupo de tareas debe asociarse con un hito de proyecto. Ese se logra cuando uno o mas productos operativos se revisan en su calidad y se aprueban



## Definicion de un conjunto de tareas para el proyecto de software
Coleccion de tareas de trabajo de ingenieria de software, hitos, productos operativos y filtros de acs que debe lograrse para completar un proyecto particular.
Con la finalidad de desarrollar un calendario, el conjunto de tareas variara dependiendo de:
	- Tipo de proyecto:
	Reingenieria, mantenimiento, prueba de concepto, nueva aplicacion, mejora de aplicacion.
	- Grador de rigor, determinado por:
		- Numero de usuarios potenciales.
		- Vitalidad de la mision (si, el proyecto requiere mision/objetivo).
		- Longevidad de la aplicacion.
		- Estabilidad de requerimientos.
		- Facilidad de comunicacion cliente/desarrollador.
		- Madurez de tecnologia aplicable.
		- Restricciones de rendimiento.
		- Caracteristicas incrustadas y no incrustadas.
		- Personal de proyecto.
		- Factores de reingenieria.

### Cronograma
Un cronograma esta compuesto por un conjunto de tareas.
Luego se ingresa, esfuerzo, duracion y fecha de inicio para cada tarea.

#### PERT (Program Evaluation and Review Technique)
Metodo para analizar tareas relacionadas a completar un proyecto, particularmente, el tiempo requerido para completar cada tarea, y para identificar el tiempo minimo requerido para completar el proyecto.

- Times defined by pert:
	- optimistic(o): the minimum possible time.
	- pessimistic time(p): the maximum possible time
	- most likely time(m): the best estimate of the time required.
	- expected time: The best estimate of the time required to accomplish an activity(te) or a path(TE).
	te = (o + 4m + p) / 6
	TE = sqrt(sumforeach(1,n, te[i]))
	where te[i] is each task from the path.
	- standard deviation of time (ote):
	ote = (p - o) / 6
	Ote = sqrt(sumforeach(1,n,ote[i] ^ 2))
	

#### Critical Path Method (CPM)
Complementary to PERT. It calculates the minimum duration of the overall project.
A critical path is determined by identifying the longest stretch of dependent activities and measuring the time required to complete them from start to finish.
Construct a model of the project that includes:
	- A list of all activities(tasks) required to complete the project.
	- The time (duration) that each activity will take to complete.
	- The dependencies between activities.
	- Logical end points such as milestones or deliverable items.

In this way
	- Each milestone is a node.
	- Each edge is an activity (which I suppose, has tasks)
